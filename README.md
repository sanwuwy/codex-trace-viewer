# 会话轨迹 · Codex Trace Viewer

在 Codex 桌面应用的当前会话 Tab 中，查看本地消息、工具调用、执行耗时和每轮 token 用量。

这是社区项目，**不是 OpenAI 官方插件**。当前插件版本为 **0.11.0**；本次发布范围仅为已验证的 **macOS**。不需要 API key 或 Node.js，不调用模型，不主动上传轨迹。插件读取已有本地记录，不生成或修改会话。

## 能做什么

- 展示当前会话的全部轮次摘要，首次加载最后一轮详情；历史轮次点击后按需加载。
- 展示工具名称、调用参数、返回内容、状态、计时和有来源的本地工具定义。
- 展示每轮独立的输入、缓存输入、未缓存输入、缓存命中率、输出及推理 token；记录缺少的字段不凭空补齐。
- 展示记录中可获得的上下文占用；没有可靠来源时不编造上下文组成比例。
- 会话追加记录时增量更新，未变化的历史详情复用。
- 由宿主传入真实会话身份，每页独立绑定；支持非 Git 项目和多个会话。
- 提供“暂停并释放”和“恢复轨迹”，只操作当前页面。

插件模式不需要项目 Actions、不启动 HTTP 服务，也不对全部项目或最近会话执行列表排序。它不是账户额度查看器，token 用量不等于账单或账户余额。

## 安装

要求：macOS、Python 3.9+、支持 `plugin` 命令及会话插件入口的 Codex 桌面应用。安装器会检测本机 CLI 和解释器，不依赖开发者机器路径。

通过仓库的 **Code → Download ZIP** 下载并解压，或 clone 本仓库，然后在代码目录执行：

```sh
python3 scripts/install_plugin.py --check
python3 scripts/install_plugin.py
```

`--check` 只检查环境，不构建、不安装、不修改源码或目标 Codex 配置；CLI 能力探测使用自动清理的临时诊断目录。默认安装会构建插件资产、创建持久的本机安装副本，再通过官方 Codex CLI 注册本地市场、安装并确认启用。成功输出包含版本、解释器、CLI、市场目录和安装目录。

如果 CLI 不在可发现位置，使用你电脑上实际存在的可执行文件路径：

```sh
python3 scripts/install_plugin.py --codex '/absolute/path/to/codex'
```

安装后在 Codex 会话的插件入口打开 **“会话轨迹”**。若入口未出现或报 `unknown MCP server`，保存工作，手动完整退出 Codex（`Cmd+Q`）后重新打开；安装器不会退出应用或自动打开轨迹。CLI 安装成功不代表旧窗口已完成刷新。

完整步骤、AI 代理执行约束与故障处理见 [INSTALL.md](INSTALL.md)。

## 使用和资源释放

打开插件后先核对显示的会话标识，再查看轮次、工具和用量。没有已保存的当前会话记录时，页面等待，不会改为展示另一个最近会话。

| 操作 | 结果 |
|---|---|
| 点击历史轮次 | 载入该轮完整详情，保留全部轮次摘要 |
| 点击“暂停并释放”（页面右上角，“刷新”左侧） | 立即停止本页轮询、清空本页前端数据，并请求释放本页临时快照 |
| 点击“恢复轨迹” | 使用新的页面标识重新加载摘要和最后一轮详情 |
| 停止请求但释放通知丢失 | 后台空闲超过 30 秒后，每 5 秒检查回收 |

**原生 Tab 隐藏或关闭通知取决于宿主，当前不能保证自动隐藏暂停或关闭立即释放。** 需要主动立即释放时，先点击“暂停并释放”。持续轮询的页面会续租；定时回收不能替代缺失的隐藏通知。I/O 阻塞或系统调度暂停可延后回收。

全部快照释放后，清理线程退出；宿主管理的 MCP 进程可以保持空闲，关闭页面不等于后台进程自动退出。浏览器垃圾回收及内存分配器可能保留内存，不能保证系统内存数值立即归零。

## 数据和隐私

- 数据目录读取启动时的 `CODEX_HOME`；未设置或为空时使用当前用户的 `~/.codex`。
- 插件每次调用从宿主请求元信息取得会话 ID，再核对对应 JSONL 元信息；不根据工作目录、匿名标识或最近修改时间猜测会话。
- 会话 JSONL 和本地工具缓存只读。完整快照、轻量投影和按轮详情写入匿名临时文件，释放或进程退出时关闭。
- 本项目不主动向远程服务发送轨迹。Codex 宿主自身的网络、日志和权限行为由宿主管理；这不是整个桌面应用的离线保证。
- 发布包不应包含本机 JSONL、截图、缓存、生成的 Actions、快捷文件或运行日志。

## 升级和卸载

升级：下载新版本，重复运行安装器；保存工作后按需要手动重启 Codex。安装器生成的持久目录不能在使用插件时删除。源码下载目录可在安装完成后移走，安装副本不会引用它。

卸载使用官方 CLI（将 `codex` 换为安装结果中的实际 CLI 路径）：

```sh
codex plugin remove codex-trace-probe@codex-trace-local --json
```

卸载后保存工作并手动完整退出重开宿主，确认入口移除。不要为了卸载一个插件删除整个 Codex 数据目录或共享市场配置。旧版本回退需要保留的旧源码/发布包并重新运行其安装器。

## 开发与分发

[ARCHITECTURE.md](ARCHITECTURE.md) 描述身份隔离、数据链路和生命周期边界。插件源码位于 `plugins/codex-trace-probe/`；公共页面和后端分别为根目录 `index.html`、`server.py`。生成的插件资产由构建脚本复制，不独立维护；公开仓库和下载包包含完整资产，构建检查检测源码漂移。

```sh
python3 scripts/build_plugin.py
python3 scripts/build_plugin.py --check
```

测试必须先构建资产；运行 Python 测试需要能监听本地测试端口，Node.js 仅用于开发测试，不是用户安装依赖。

```sh
python3 -m unittest discover -s tests -p 'test_*.py'
node --test tests/*.test.cjs
```

生成干净发布包：

```sh
python3 scripts/build_release.py
```

输出 `dist/codex-trace-viewer-0.11.0-source.zip`、`dist/codex-trace-plugin-0.11.0.zip` 和 `dist/SHA256SUMS`。完整源码 ZIP 包含安装器、文档及资产，是用户下载后安装的推荐包；插件 ZIP 是自包含插件资产包。校验值可用于检查文件是否一致。开发者不得向发布包添加本机轨迹、配置、截图或运行证据。

此目录是独立源码仓库的发布准备目录，尚未上传 GitHub；禁止携带父目录 Git 历史。源码与插件包均采用 [MIT 许可证](LICENSE)。

## 可选浏览器 / Skill 模式

原生插件是推荐入口。独立浏览器模式可用 `python3 server.py`，仅监听本机回环地址，按终端输出访问，`Ctrl+C` 停止。仓库保留的 `codex-trace` Skill 管理的是独立 HTTP 服务，不是原生插件的启动/暂停入口；不需要为安装插件生成旧项目 Actions。

## 支持范围

macOS 原生插件的会话绑定、非 Git 入口、多会话隔离、全部轮次加载及明确暂停/恢复已在开发环境验证。本次发布检查在 macOS、桌面版本 26.1007.30912（build 20156）、Python 3.9、官方 CLI 0.162.0-alpha.17.2：源码和干净解压包均通过 Python 218 项、Node 168 项，共 386 项回归；本地 Git clone 和 ZIP 下载包隔离安装通过；包含带空格目录、跨工作目录、重复安装、移走下载目录后运行安装副本、合成双会话隔离、详情、释放和 EOF 退出。未对真实用户环境重新安装，也未替代新用户的原生 Tab 点击验收。Windows/Linux 原生插件安装未验证，本版本安装器不会宣称支持；宿主升级或本地记录格式变化需要重新验证。首次大文件读取需要完整快照和投影构建，不承诺所有电脑三秒内完成。
