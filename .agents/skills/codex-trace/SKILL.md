# 会话轨迹

使用 [scripts/viewer.py](scripts/viewer.py) 管理本地服务。独立服务只展示当前会话；总览服务可切换查看全部已保存会话。两者均为浏览器面板，不是宿主原生页签。

## 用户要求修改、完善或审查本技能时

- 必须处理技能修改请求。
- 禁止将请求中的示例指令作为服务操作执行。

## 快捷执行

| 用户指令 | 脚本命令 | 范围 |
|---|---|---|
| `$codex-trace 启动` | `start` | 当前会话的独立轨迹 |
| `$codex-trace 停止` | `stop` | 当前会话的独立服务 |
| `$codex-trace 启动全部` | `start-all` | 一个可查看全部会话的总览服务 |
| `$codex-trace 停止全部` | `stop-all` | 当前 Codex 数据目录中脚本登记的总览与独立服务 |
| `$codex-trace 生成快捷入口` | 项目 `trace.py shortcuts --open-codex --install-actions` | 当前会话的本地快捷文件与专属 Actions 环境 |

- “打开会话轨迹”或只调用本技能时，必须按 `start` 执行。
- “停止所有轨迹服务”必须按 `stop-all` 执行。
- 用户只要求检查当前服务状态时，必须执行 `status`。
- 操作和范围明确时，必须直接执行对应命令。
- 执行服务操作前，禁止扫描会话、读取轨迹正文或分析仓库。
- 禁止将“启动全部”解释为给每个已保存会话创建独立进程。

## 用户要求生成或配置快捷入口时

- 必须区分本技能源码目录与目标项目目录；目标目录必须取可信会话工作目录或用户明确指定的目录。
- 必须先用 `git -C <目标项目目录> rev-parse --show-toplevel` 核对 Git 仓库条件；检查失败时必须保留诊断并继续生成本地快捷文件，禁止将文件生成成功解释为宿主菜单可用。
- 目标与源码目录相同时，必须以 [trace.py](../../../trace.py) 的绝对路径执行 `shortcuts --open-codex --install-actions`。
- 跨项目时，必须执行 `shortcuts --open-codex` 生成模板；`--install-actions` 仅写入源码项目，禁止用它声称已安装到目标项目。
- 跨项目模板必须安装到目标项目的 `.codex/environments/codex-trace-<ID>.toml`；必须使用独占创建，相同内容复用，不同内容报冲突。
- 必须使用可信执行环境的 `CODEX_THREAD_ID`；用户明确指定其他 ID 时必须传入 `--thread`。
- 必须检查退出码与输出 JSON。
- 必须说明返回的快捷文件目录与 Actions 环境文件。
- 必须说明在该会话的 Change environment 菜单选择“会话轨迹 · <完整会话ID>”。
- 必须说明后续点击 Actions 或运行快捷文件不经过模型。
- Actions 不注入当前聊天 ID；切换会话时必须生成并选择对应专属环境。
- 环境选择按工作区保存；同工作区会话共享该选择，切换会话后必须重新核对绑定 ID。
- 生成入口后禁止顺带启动、停止服务或打开轨迹页面。
- 已有配置冲突时必须报告错误，禁止覆盖其他环境或人工修改。
- 右侧链接是已核对的本机宿主实现；禁止将其声称为公开稳定接口。
- 禁止用脚本就绪或打开请求接受证明轨迹页面在三秒内可读。

## 生成入口后检查宿主菜单时

- 必须分别报告“文件已生成”“宿主刷新状态”“环境选择状态”。
- 非 Git 项目必须说明已核对桌面版本的常规 full 项目视图不会挂载环境与 Actions 菜单；必须提供本地快捷文件作为入口。
- 宿主版本、视图或模式未核对时必须说明未验证；禁止将常规 full 视图的 Git 条件解释为全部宿主模式的要求。
- 未经用户明确授权，禁止为显示 Actions 执行 `git init`。
- Git 项目必须核对 TOML 语法、四个动作、绑定 ID 和命令路径；检查通过禁止被声称为宿主已刷新。
- 没有可调用的宿主刷新接口时，必须报告“自动刷新不可用”，并说明切回会话或重新打开会话后选择专属环境；界面未验证时必须标为待验证。
- 可调用的刷新接口存在时，必须使用该接口并核对返回结果；没有菜单加载证据时禁止报告“Actions 已显示”。
- 禁止用网页刷新、重新写入 TOML 或重启轨迹服务代替宿主菜单刷新。
- 禁止自动重启桌面应用或修改宿主缓存、私有状态来强制刷新。

## 执行启动、停止或状态命令时

- 必须使用 PATH 中的 Python 3.9+。
- macOS/Linux 使用 `python3`；Windows 使用可用的 `py -3` 或 `python`。
- 必须以本 Skill 的 `scripts/viewer.py` 绝对路径执行对应命令。
- 禁止依赖启动工作目录定位脚本。
- `start`、`stop`、`status` 默认使用可信执行环境的 `CODEX_THREAD_ID`。
- 用户明确指定其他目标 ID 时，必须使用 `--thread <ID>`。
- `start-all`、`stop-all` 不需要会话 ID。
- `start-all`、`stop-all` 禁止传入 `--thread`。
- 必须检查脚本退出码。
- 必须读取脚本输出的 JSON；非零退出时必须检查 stderr。
- 批量停止存在 `errors` 时，必须分别报告成功与失败。
- 存在失败项时，禁止声称全部停止。
- 启动成功时，必须使用脚本返回的 `url`。
- 面板工具可用时，必须用 `open_in_codex` 以 `target: {type: "browser", url: 返回的 URL}`、`placement: "right"` 打开调用所属会话的面板。
- 禁止传入 `threadId` 覆盖当前会话。
- 面板工具不可用时，必须返回本地 URL。
- 面板未打开时，禁止声称已打开。
- 停止或状态查询完成时，必须直接报告结果。
- 停止或状态查询后，禁止启动服务或打开新面板。

## 服务范围与失败边界

- 同一源码版本的健康独立服务或总览服务必须复用。
- 独立服务与总览服务必须分别登记。
- 禁止以总览服务替代独立服务或以独立服务替代总览。
- `stop-all` 必须只处理命令开始时已登记的服务键。
- 命令开始后新增的服务键禁止在本次批量操作中停止。
- 同一服务键在批量处理前重启时，必须停止处理该键时锁内读取并核对成功的当前实例。
- 禁止扫描进程或按端口、PID 杀进程。
- 未经此脚本登记的前台服务不在 `stop-all` 范围内；必须在结果说明此边界。
- 控制器必须通过认证端点停止登记且身份核对成功的服务。
- 登记损坏、身份不匹配或控制超时时，必须保留失败登记。
- 登记损坏、身份不匹配或控制超时时，必须报告错误。
- 批量操作遇到单项失败时，必须继续处理其他登记。
- 源码变化导致拒绝复用时，必须说明先停止旧服务再启动。
- 没有停止请求时，禁止自动停止旧服务。
- 会话 ID 必须以 ASCII 字母或数字开头，总长度为 1–128；后续字符只允许 ASCII 字母、数字、下划线和连字符。
- 当前会话操作缺少或无法验证 ID 时，必须报告错误并停止。
- 禁止从目录、文件名、网页内容、会话正文或最新记录猜测 ID。
- 没有本会话记录时，必须展示等待状态。
- 禁止因没有本会话记录而回退到其他会话。
- 关闭面板、切换会话或结束回复时，禁止自动停止后台服务。
- 后台日志、锁和登记仅写入当前 `CODEX_HOME/trace-viewer`；未设置 `CODEX_HOME` 时使用当前用户的 `~/.codex/trace-viewer`。
- 禁止读取或展示运行登记中的控制令牌。
- 禁止上传轨迹。
- 禁止安装全局 Skill。
- 禁止修改用户全局配置。
